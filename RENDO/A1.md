## 2. STRIDE Threat Analysis & Mitigations

Below is an analysis of potential threats across the six STRIDE categories, mapped to the **OWASP Top 10:2025**, along with the specific mitigations implemented in this project.

### S - Spoofing
- **Threat:** An attacker steals another user's session token and spoofs their identity to access their profile or perform actions on their behalf.
- **OWASP Category:** A07:2025 Identification and Authentication Failures
- **Mitigation:** The JWT is stored in a `secure`, `httpOnly`, and `sameSite: 'strict'` cookie, making it inaccessible to JavaScript-based theft (XSS) and safe from Cross-Site Request Forgery (CSRF).

### T - Tampering
- **Threat:** An attacker intercepts the HTTP request and modifies the role parameter during registration (e.g., changing their role from `customer` to `admin`) to gain unauthorized privileges.
- **OWASP Category:** A08:2025 Software and Data Integrity Failures
- **Mitigation:** We enforce strict server-side schema validation using `zod` to explicitly reject unregistered or restricted roles during account creation.

### R - Repudiation
- **Threat:** A company denies that they added a specific staff member, and there is no trace of who performed the action.
- **OWASP Category:** A09:2025 Security Logging and Monitoring Failures
- **Mitigation:** The `verifyToken` middleware decodes the JWT and attaches the `userId` to every authenticated request (`req.userId = decoded.id`), ensuring that every action handled by controllers can be tied back to a specific, verified identity in the database.

### I - Information Disclosure
- **Threat:** An attacker dumps the SQLite database and reads the plaintext passwords of all registered users.
- **OWASP Category:** A02:2025 Cryptographic Failures
- **Mitigation:** Passwords are never stored in plaintext. They are hashed using a slow adaptive hash (`bcrypt.hash(password, 10)`), rendering stolen database rows useless for credential harvesting.

### D - Denial of Service
- **Threat:** An attacker continuously bombards the `/api/auth/login` endpoint with rapid requests, overwhelming the server and preventing legitimate users from logging in.
- **OWASP Category:** A04:2025 Insecure Design (specifically regarding resource exhaustion and rate limiting)
- **Mitigation:** The `express-rate-limit` package is implemented on the `/login` route to strictly limit each IP to 5 requests per 15-minute window.

### E - Elevation of Privilege
- **Threat:** A standard `worker` attempts to access the company-only endpoint (`/api/roles/company/staff`) to secretly add their own accounts to the system.
- **OWASP Category:** A01:2025 Broken Access Control
- **Mitigation:** The `roleMiddleware` operates on a default-deny principle, explicitly checking the user's role and returning a live `403 Forbidden` response if they attempt to access an unauthorized endpoint.
