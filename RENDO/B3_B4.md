# B3 & B4: Practical Execution & Presentation Guide

This document is your script/guide for executing the live presentation required for **B3** and **B4**.

## 1. Live End-to-End Run (B3)
**To present this to your grader:**
1. **The Commit:** Show them your GitHub repository. Open the `Jenkinsfile` file to prove that you have an automated pipeline containing testing and security scans.
2. **The Run:** Go to your Jenkins Dashboard. Show them a recent successful run where the code was checked out, scanned with SonarQube, tested via Newman, and pushed to Docker Hub.
3. **The Deploy:** Open your terminal and show your Kubernetes manifests:
   ```bash
   kubectl apply -f k8s/
   kubectl get pods
   ```
   Show them the output where the pods are running under the blue deployment.

## 2. Triggering a Failure & Self-Healing (B3)
**To prove High Availability (or Blue-Green strategy):**
1. Open Postman and hit your `https://localhost/health` endpoint through your Nginx Ingress.
2. Tell the grader: *"I am going to simulate a Blue-Green deployment switch."*
3. Open `k8s/service.yaml` and change `version: blue` to `version: green`. Run `kubectl apply -f k8s/service.yaml`.
4. Immediately hit the `/health` endpoint again in Postman.
5. **The Result:** Traffic instantly switches to the Green deployment with zero downtime!

## 3. Going Deep on Security (B3/B4)
*The rubric asks you to go deep on either Scalability, Security, or Cost.*
**Your Script:**
"Because our team also focused heavily on Track A (Security), we integrated security directly into our DevOps pipeline (DevSecOps). 
- We don't run our Docker containers as `root`, we run them as a restricted `node` user.
- Our `Jenkinsfile` automatically runs SAST (SonarQube) and DAST (OWASP ZAP) scans before deployment.
- We use Nginx Ingress to terminate SSL/TLS, ensuring that all data in transit from the client to our cluster is fully encrypted."

## 4. Q&A Preparation (B4)
Here are the answers to the trade-off questions your grader might ask:

**Q: Why did you choose Kubernetes over Docker Compose for Orchestration?**
A: "We used Docker Compose to provision our local environment and monitoring stack, but we chose Kubernetes (Minikube) for orchestration because it provides robust primitives for advanced deployment strategies like Blue-Green, automatic self-healing of pods, and seamless integration with GitOps tools like ArgoCD."

**Q: What happens if your server hardware fails completely?**
A: "We have a Disaster Recovery plan. Our `backup.sh` script hot-copies our database dump. In a real-world scenario, a cron job ships the backup to an off-site storage bucket. Because we use IaC and Kubernetes, we can spin up a new cluster, apply our manifests, restore the DB, and be back online in minutes."
