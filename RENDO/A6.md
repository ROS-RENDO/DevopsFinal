# A6: Security Testing (SAST + DAST) Guide

Because **SAST** (Static Application Security Testing) and **DAST** (Dynamic Application Security Testing) require external servers and scanning tools, **you must execute these steps manually** to fulfill the A6 grading criteria.

## Part 1: SAST (SonarQube)
*SAST scans your source code for vulnerabilities and security hotspots without running the application.*

1. Start your local SonarQube instance (from the Week-12 Lab).
2. Create a new project in SonarQube.
3. Run the `sonar-scanner` CLI tool in your `backend` folder, passing your project key.
4. **Demonstrate to your Grader:** 
   - Open the SonarQube Dashboard.
   - Show the **Quality Gate** status.
   - Click on the **Security Hotspots** or **Vulnerabilities** tab and show them at least one finding (even if it's an informational or false-positive warning).

## Part 2: DAST (OWASP ZAP)
*DAST attacks the running application from the outside, just like a real hacker, to find runtime vulnerabilities.*

1. Make sure your server is running (`npm run dev`).
2. Open **OWASP ZAP**.
3. Perform an **Automated Scan** against `https://localhost:5000`.
4. **Demonstrate to your Grader:**
   - Wait for the Active Scan to finish.
   - Open the **Alerts** tab.
   - Show them at least one finding (e.g., Missing Anti-clickjacking Header, X-Content-Type-Options missing, etc.).

## Part 3: Remediating a Finding
To get the final 3 points, you must pick one finding from either SonarQube or ZAP, fix it in the code, and rescan to prove it's gone. 

*(If you find a Missing Security Header in ZAP, you can easily fix it by running `npm install helmet` and adding `app.use(require('helmet')())` to your `server.js`!)*
