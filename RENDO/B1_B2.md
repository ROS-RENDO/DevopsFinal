# B1 & B2: DevOps Principles & Technical Implementation

This document provides the mapping and evidence for the **B1 (DevOps Principles & Culture)** and **B2 (Technical Implementation)** grading criteria.

## 1. Toolchain Mapping (B1)
Here is the mapping from our lifecycle to the tools we implemented:
* **Plan:** Jira (where we tracked our tasks)
* **Code:** GitHub (Git version control, branches, and PR reviews)
* **Build & Test:** Jenkins (Automated CI Pipeline) + Postman/Newman (Automated Tests)
* **Deploy:** Kubernetes (Minikube/k3s) for Orchestration + Docker Compose for Provisioning
* **Monitor:** Loki + Grafana (Logging) + Prometheus + Grafana (Monitoring)

## 2. Technical Implementation Evidence (B2)

* **B2.1 Infrastructure (IaC):** We use `docker-compose.yml` to provision the environment locally, and a dedicated `monitoring/docker-compose.yml` to provision our entire logging and metrics stack.
* **B2.2 CI Pipeline & Tests:** We created a declarative `Jenkinsfile`. This pipeline triggers on code changes, runs SAST (SonarQube) and DAST (OWASP ZAP) scans, builds the Docker image, and executes our `tests/postman_collection.json` via Newman.
* **B2.3 Deployment Strategy:** We use a **Blue-Green** deployment strategy on Kubernetes. We have `k8s/deployment-blue.yaml` and `k8s/deployment-green.yaml`. We switch traffic instantly by updating the label selector in `k8s/service.yaml`.
* **B2.4 Containerization:** We wrote a multi-stage `Dockerfile` and our Jenkins pipeline automatically pushes the finished image to **Docker Hub**.
* **B2.5 & B2.7 Orchestration & High Availability:** Our Kubernetes cluster orchestrates the application. The `service.yaml` acts as an internal load balancer between our 2 replicas, and our Nginx `ingress.yaml` safely exposes the app to the outside world.
* **B2.6 Scaling:** Scaling in Kubernetes is easy. We can simply run `kubectl scale deployment backend-blue --replicas=5`.
* **B2.8 Backup & DR:** We created `scripts/backup.sh` which uses a DB Dump to safely back up our SQLite database without corruption. This script is designed to run on a cron job.
* **B2.9 Logging:** We implemented **Loki + Grafana**. Our `monitoring/docker-compose.yml` uses Promtail to scrape the local `backend/logs/*.log` files and sends them to Loki, allowing us to search all structured logs in Grafana.
